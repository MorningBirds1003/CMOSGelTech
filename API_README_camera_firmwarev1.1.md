# Camera Firmware API README

API README for `camera_firmwarev1.1.py`, a NexiGo N680E Pro / USB UVC camera scaffold with interactive startup mode selection, focus calibration, persistent settings, and fixed-count image capture.

This README is focused on the exact function-call sequence needed to expose calibration mode on startup and to let an external script, GUI, touchscreen, or device controller invoke the same startup behavior without rewriting the camera/capture logic. Note, this is a running log but should include everything from the code in camera_firmwarev1.1.py. 

One of note: when running the code, many things are limited to the nexigo camera specificall, particularly lighting and zoom. Specifically, I don't know the exact quantities that the zoom goes in(lens rotation) but I can call it with opencv so I adjust based on that. There is a time delay between focus operations and I would be more than happy to give a demo and accept feedback if you see something that could be fixed with it. 

This package currently runs on version 4.13.0.92 of opencv. I do not know if it would work on future versions so I recommend having a copy unless you want to update the code with opencv versions. I tried to use as low level functions in opencv as necessary but my past experience shows that opencv sometimes changes the logic in these low level functions with future updates.

## 1. Core Startup Modes

The script supports these high-level modes:

| User-facing startup option | Internal mode string | Purpose | Returns to menu? |
|---|---:|---|---:|
| `1` | `"calibrate"` | Choose save directory, open camera, launch live focus calibration window, persist focus settings | Yes |
| `2` | `"main"` | Run the standard capture sequence using saved focus/output settings | No |
| `3` | `"set-output-dir"` | Change only the save directory and persist it | Yes |
| `4` | `"exit"` | Exit the program | No |

The important design point is that calibration and save-directory selection are **startup-callable modes**, not hidden UI-only behavior. That means a parent script can call the same functions directly.

## 2. Minimal Interactive Startup Flow

Running the script normally:

```bash
python camera_firmwarev1.1.py
```

enters the default `prompt` mode. The call sequence is:

```text
main()
  configure_logging()
  args = parse_args()
  settings_path = Path(args.settings)
  settings_manager = SettingsManager(settings_path)

  while True:
      selected_mode = choose_startup_mode()
      return_to_menu = run_camera_mode_once(
          selected_mode,
          args,
          settings_path,
          settings_manager,
      )

      if not return_to_menu:
          break
```

The startup menu is generated by:

```python
selected_mode = choose_startup_mode()
```

which returns one of:

```python
"calibrate"
"main"
"set-output-dir"
"exit"
```

## 3. Exact Function-Call Sequence for Calibration Mode on Startup

When the operator chooses `1` at startup, `choose_startup_mode()` returns:

```python
"calibrate"
```

That mode is then routed through:

```python
return_to_menu = run_camera_mode_once(
    selected_mode="calibrate",
    args=args,
    settings_path=settings_path,
    settings_manager=settings_manager,
)
```

Inside `run_camera_mode_once("calibrate", ...)`, the exact sequence is:

```text
run_camera_mode_once("calibrate", args, settings_path, settings_manager)
  config = build_default_config(settings_path)
      AppConfig(storage=StorageConfig(settings_file=str(settings_path)))
      SettingsManager(settings_path).apply_to_config(config)

  _apply_cli_overrides(args, settings_manager, config)

  if selected_mode == "calibrate" and args.output_dir is None:
      choose_and_save_output_directory(settings_manager, config)
          prompt_for_directory(config.storage.output_dir)
          config.storage.output_dir = selected_dir
          settings_manager.update_storage_output_dir(selected_dir)

  _log_active_config("calibrate", settings_path, config)

  manager = build_manager(config)
      camera = OpenCVCamera(config.camera)
      load_cell = LoadCellInterface()
      hooks = ExternalDeviceHooks()
      manager = CaptureManager(config, camera, load_cell, hooks)

  try:
      manager.initialize()
          hooks.initialize()
          camera.open()
              cv2.VideoCapture(...)
              camera._negotiate_resolution()
              camera.apply_focus_settings()
              camera.flush_frames(...)
          load_cell.initialize()

      run_calibration_mode(manager, settings_manager, config, output_dir=config.storage.output_dir)
          CalibrationManager(manager.camera, settings_manager, config.storage).run(output_dir=...)
              settings_manager.update_storage_output_dir(output_dir)
              open live preview window
              process keyboard focus controls
              save calibration frames if requested
              settings_manager.update_focus(autofocus, manual_focus_value)
              destroy calibration window

      return True

  finally:
      manager.shutdown()
          camera.close()
          load_cell.shutdown()
          hooks.shutdown()
```

The returned `True` tells `main()` to go back to the startup menu after calibration closes.

## 4. Direct API Usage: Open Calibration Mode From Another Script

Because `camera_firmwarev1.1.py` contains a period in the filename, direct Python import syntax like `import camera_firmwarev1.1` will not work cleanly. For API-style reuse, either rename the file to something importable, such as:

```text
camera_firmware_v1_1.py
```

or load it dynamically.

### Recommended: rename to an importable module

```python
from pathlib import Path
from argparse import Namespace

from camera_firmware_v1_1 import (
    configure_logging,
    SettingsManager,
    run_camera_mode_once,
)

configure_logging()

settings_path = Path("camera_settings.json")
settings_manager = SettingsManager(settings_path)

args = Namespace(
    mode="calibrate",
    camera_index=None,
    output_dir=None,
    settings=str(settings_path),
    shot_count=None,
    interval=None,
    prefix="N680E_sequence",
)

return_to_menu = run_camera_mode_once(
    selected_mode="calibrate",
    args=args,
    settings_path=settings_path,
    settings_manager=settings_manager,
)
```

This is the closest direct equivalent of choosing `1` from the startup prompt.

### Fully programmatic calibration without startup menu

```python
from pathlib import Path

from camera_firmware_v1_1 import (
    configure_logging,
    SettingsManager,
    build_default_config,
    build_manager,
    run_calibration_mode,
)

configure_logging()

settings_path = Path("camera_settings.json")
settings_manager = SettingsManager(settings_path)
config = build_default_config(settings_path)

# Optional API-side overrides before opening camera
config.camera.camera_index = 1
config.storage.output_dir = "captures"
settings_manager.update_storage_output_dir(config.storage.output_dir)

manager = build_manager(config)

try:
    manager.initialize()
    run_calibration_mode(
        manager=manager,
        settings_manager=settings_manager,
        config=config,
        output_dir=config.storage.output_dir,
    )
finally:
    manager.shutdown()
```

Use this form when your external program already knows it wants calibration and does not need the human startup prompt.

## 5. Direct API Usage: Programmatic Startup Selector

A custom GUI, touchscreen, serial interface, or hardware panel can replace `choose_startup_mode()` as long as it passes the same mode strings into `run_camera_mode_once()`.

```python
from pathlib import Path
from argparse import Namespace

from camera_firmware_v1_1 import SettingsManager, run_camera_mode_once

settings_path = Path("camera_settings.json")
settings_manager = SettingsManager(settings_path)

args = Namespace(
    mode="prompt",
    camera_index=None,
    output_dir=None,
    settings=str(settings_path),
    shot_count=None,
    interval=None,
    prefix="N680E_sequence",
)

def map_button_to_mode(button_id: int) -> str:
    if button_id == 1:
        return "calibrate"
    if button_id == 2:
        return "main"
    if button_id == 3:
        return "set-output-dir"
    if button_id == 4:
        return "exit"
    raise ValueError(f"Unsupported startup button: {button_id}")

button_id = 1  # Example: calibration button pressed
selected_mode = map_button_to_mode(button_id)

return_to_menu = run_camera_mode_once(
    selected_mode=selected_mode,
    args=args,
    settings_path=settings_path,
    settings_manager=settings_manager,
)
```

The external UI only needs to supply one of the valid mode strings. The firmware module handles settings, camera initialization, calibration, capture, and shutdown.

## 6. Non-Interactive CLI Equivalents

The same startup modes can be called from the command line without the prompt.

### Calibration mode

```bash
python camera_firmwarev1.1.py --mode calibrate
```

Runs save-directory selection, opens the camera, launches the calibration preview, saves focus settings on quit, and exits.

### Calibration mode with explicit save directory

```bash
python camera_firmwarev1.1.py --mode calibrate --output-dir ./captures/sample_set_01
```

Skips the interactive save-directory prompt because `--output-dir` is already supplied.

### Main capture mode using saved calibration

```bash
python camera_firmwarev1.1.py --mode main
```

Loads `camera_settings.json`, applies the saved focus/output settings, opens the camera, and runs the default four-shot capture sequence.

### Main capture mode with overrides

```bash
python camera_firmwarev1.1.py --mode main --prefix sample_A --shot-count 4 --interval 1.0
```

Runs the same capture path as startup option `2`, but with explicit filename prefix, shot count, and shutter interval.

## 7. Calibration Window Controls

Inside calibration mode, the preview window supports:

| Key | Action |
|---|---|
| `q` or `Esc` | Save current focus settings and close calibration |
| `a` | Toggle autofocus on/off |
| `[` | Decrease manual focus by 5 |
| `]` | Increase manual focus by 5 |
| `-` | Decrease manual focus by 1 |
| `+` or `=` | Increase manual focus by 1 |
| `s` | Save the current full-resolution calibration frame |

When the calibration window closes, the script persists:

```json
{
  "storage": {
    "output_dir": "..."
  },
  "camera": {
    "autofocus": true,
    "manual_focus_value": null
  }
}
```

or, for manual focus:

```json
{
  "storage": {
    "output_dir": "..."
  },
  "camera": {
    "autofocus": false,
    "manual_focus_value": 123
  }
}
```

## 8. Persistent Settings Contract

The persistent settings file defaults to:

```text
camera_settings.json
```

Settings are read through:

```python
config = build_default_config(settings_path)
```

which internally calls:

```python
SettingsManager(settings_path).apply_to_config(config)
```

The currently persisted fields are:

```json
{
  "storage": {
    "output_dir": "path/to/captures"
  },
  "camera": {
    "autofocus": true,
    "manual_focus_value": null
  }
}
```

The main mode depends on this settings contract. It does not ask for focus again; it uses whatever calibration mode saved previously.

## 9. Important API Entry Points

### `choose_startup_mode()`

Interactive terminal selector.

```python
selected_mode = choose_startup_mode()
```

Returns:

```python
"calibrate" | "main" | "set-output-dir" | "exit"
```

Replace this function if a non-terminal UI will choose startup behavior.

### `run_camera_mode_once(selected_mode, args, settings_path, settings_manager)`

Main router for one mode.

```python
return_to_menu = run_camera_mode_once(
    selected_mode,
    args,
    settings_path,
    settings_manager,
)
```

Returns:

```python
True   # mode completed and caller should show startup menu again
False  # mode completed and program should exit or remain in terminal mode
```

### `run_calibration_mode(manager, settings_manager, config, output_dir=None)`

Launches calibration using an already initialized `CaptureManager`.

```python
run_calibration_mode(manager, settings_manager, config, output_dir=config.storage.output_dir)
```

This is the cleanest direct function to call when you already have a configured and initialized manager.

### `choose_and_save_output_directory(settings_manager, config)`

Prompts for a save path, updates active config, and persists it.

```python
selected_dir = choose_and_save_output_directory(settings_manager, config)
```

Useful if a parent UI wants to expose save-directory setup as a separate startup mode.

### `run_main_mode(manager, prefix="N680E_sequence", shutter_interval_s=None, shot_count=None)`

Runs the normal capture sequence using the active config.

```python
results = run_main_mode(manager, prefix="sample_A", shot_count=4, shutter_interval_s=1.0)
```

Returns:

```python
[
    (image_path, metadata_path, load_value),
    ...
]
```

## 10. Recommended External Controller Pattern

For a device UI, keep the firmware API boundary at the mode-string level:

```python
mode = external_ui.get_selected_camera_mode()

return_to_menu = run_camera_mode_once(
    selected_mode=mode,
    args=args,
    settings_path=settings_path,
    settings_manager=settings_manager,
)

if return_to_menu:
    external_ui.show_startup_menu_again()
else:
    external_ui.close_or_continue_terminal_mode()
```

Use these exact mode strings:

```python
VALID_STARTUP_MODES = {
    "calibrate",
    "main",
    "set-output-dir",
    "exit",
}
```

Do not call `CalibrationManager.run()` directly from an external UI unless you are also handling camera initialization and shutdown yourself. The safer sequence is:

```text
build_default_config()
build_manager()
manager.initialize()
run_calibration_mode()
manager.shutdown()
```

or simply:

```text
run_camera_mode_once("calibrate", ...)
```

## 11. Current Limitations / Notes

- Lighting is not controlled through this API; the script assumes manual external illumination.
- Focus control depends on what the camera driver exposes through OpenCV/UVC.
- `LoadCellInterface` is a placeholder and currently returns a dummy value.
- `ExternalDeviceHooks` is intentionally provided for future integration with motors, DAQs, embedded controllers, or other device APIs.
- The filename `camera_firmwarev1.1.py` is not ideal for Python imports because of the extra period. Rename it before treating it as a normal Python module.

That is the function-call sequence to preserve if you extract or wrap calibration mode for another startup API.
